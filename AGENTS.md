# LinkedIn Insights Pro - Agent Guidelines

## Build & Development Commands

```bash
pnpm dev                 # SPA + Worker in workerd (http://localhost:5173)
pnpm build               # Production build (top-level Wrangler config)
pnpm typecheck           # App + Worker type checks
pnpm lint                # ESLint, zero warnings allowed
pnpm lint:fix            # ESLint with fixes
pnpm format              # Prettier
pnpm test                # Vitest in workerd; `pnpm test --run` for one pass

pnpm db:generate         # Generate a D1 migration from db/schema.ts
pnpm db:migrate:local    # Apply migrations to local D1
pnpm db:migrate          # Apply migrations to remote top-level D1
pnpm db:health           # SELECT 1 against remote D1
pnpm db:smoke            # Schema assertions
pnpm create-admin <email> <password> [--remote] [--env preview|production]
pnpm bench:limits        # Measure Workers Free headroom
```

Deploy commands are human-gated; see `docs/deployment.md`.

```bash
pnpm deploy               # top-level config (placeholder DB id)
pnpm deploy:preview       # CLOUDFLARE_ENV=preview build + wrangler deploy --env preview
pnpm deploy:production    # CLOUDFLARE_ENV=production build + wrangler deploy --env production
pnpm exec wrangler deploy --dry-run [--env preview|production]
```

## Project Architecture

- **Frontend**: React 19 + TypeScript + Vite, hash-based routes
  (`#/dashboard`, `#/profiles`, `#/leads`, `#/settings`, `#/admin`, `#/login`)
- **Runtime**: one Cloudflare Worker (`worker/index.ts`) with an `ASSETS`
  static-assets binding. `/api/*` enters the route table; everything else is
  served by `env.ASSETS.fetch`.
- **Database**: Cloudflare D1 (SQLite), Drizzle ORM `sqlite-core`, binding
  name `DB`
- **Auth**: opaque Session Tokens stored in D1, resolved per request; PBKDF2-
  SHA512 password hashes in `salt:hash` hex format
- **Scraping**: provider adapters over plain `fetch` (`worker/providers/`);
  Apify and treg, selected by the User
- **Credentials**: per-User Scrape Credentials encrypted with AES-GCM
- **Background work**: a daily Cron Trigger (`0 3 * * *`) deletes Scrape Jobs
  and their items after seven days

No Node.js compatibility flags are enabled. Worker code must use Web APIs:
`fetch`, `crypto.subtle`, `TextEncoder`, `Request`/`Response`, D1. There is no
`process`, `fs`, `Buffer`, `pg`, or Node HTTP server.

## File Naming

- Components/Pages: `PascalCase.tsx` (`Navbar.tsx`, `Dashboard.tsx`)
- Worker routes/providers/services/lib: `camelCase.ts` (`auth.ts`,
  `scrape.ts`, `jobs.ts`, `apify.ts`, `credentials.ts`)
- Database: `db/schema.ts`, `worker/db.ts`
- Tests: `<feature>.test.ts` under `test/`
- Migrations: generated by `pnpm db:generate` into `drizzle-d1/`; never rename
  or edit applied files

## Worker Route Pattern

Every route module exports `Route[]` and is composed in
`worker/routes/index.ts`:

```typescript
import { error, json, parseJsonBody, requireUser, type Route } from '../http';
import { createDb } from '../db';

export const exampleRoutes: Route[] = [
  {
    method: 'POST',
    path: '/api/example',
    handler: async (ctx) => {
      const user = await requireUser(ctx);
      if (user instanceof Response) return user;

      const body = await parseJsonBody(ctx.request);
      if (typeof body.name !== 'string') return error(400, 'name is required');

      const db = createDb(ctx.env.DB);
      const rows = await db.select().from(exampleTable).limit(1);
      return json(rows);
    },
  },
];
```

- Handlers return a `Response`; helpers (`json`, `text`, `error`) build one.
- `requireUser` and `requireAdmin` return either the row/User or a ready 401/403
  `Response`; check `instanceof Response` and return it.
- `parseJsonBody` returns `{}` for an empty or invalid body; validate fields
  explicitly.
- `ctx.env` is the Worker `Env` (`DB`, `ASSETS`,
  `CREDENTIAL_ENCRYPTION_KEY`); `ctx.ctx` is `ExecutionContext`.

## Authentication

```typescript
// Client: opaque token from localStorage, sent as a Bearer header
import { authClient } from '@/lib/auth';
const session = authClient.getSession();
const headers = authClient.getAuthHeaders();

// Worker: resolve the User from the Authorization header
import { requireUser } from '../http';
const user = await requireUser(ctx);
if (user instanceof Response) return user;
```

- Tokens are 32 random bytes, lowercase hex, stored in `sessions`, and expire
  after 30 days.
- Passwords use PBKDF2-SHA512, 10,000 iterations, 512 bits, 16-byte salt,
  stored as `salt:hash`. Keep these parameters; existing hashes depend on them.
- Sign-out deletes the session row. There is no JWT and no client-trusted role
  claim: the role is read from `user_roles` on each admin request.

## Database Operations (Drizzle + D1)

```typescript
import { eq, and, desc, inArray } from 'drizzle-orm';
import { createDb, chunk } from '../db';

const db = createDb(ctx.env.DB);

await db
  .select()
  .from(linkedinProfiles)
  .where(and(eq(linkedinProfiles.ownerId, user.id), eq(linkedinProfiles.profileUrl, url)))
  .orderBy(desc(linkedinProfiles.createdAt))
  .limit(10);

await db.insert(linkedinProfiles).values(data).returning();
await db.update(linkedinProfiles).set(update).where(eq(linkedinProfiles.id, id)).returning();
await db.delete(linkedinProfiles).where(eq(linkedinProfiles.id, id));

// Atomic multi-statement writes. Drizzle emits one D1 statement per query.
await db.batch([db.insert(users).values(user), db.insert(userRoles).values(role)]);

// D1 allows at most 100 bound parameters per statement.
for (const ids of chunk(userIds, 90)) {
  await db.delete(leads).where(inArray(leads.id, ids));
}
```

- Always scope reads and writes by `ownerId` for non-admin data.
- Use `db.batch()` for coupled writes; both statements then run together in
  one D1 batch.
- Keep per-invocation D1 statements and `fetch` calls under Workers Free limits
  (50 each); `pnpm bench:limits` records the current counts.
- Dates are ISO 8601 strings; IDs are UUID strings generated with
  `crypto.randomUUID()`.

## Naming Conventions

- **DB columns**: `snake_case` (`created_at`, `owner_id`, `profile_url`)
- **TS fields**: `camelCase` (`createdAt`, `ownerId`, `profileUrl`)
- **API payloads**: `snake_case` where the SPA already expects it; keep existing
  field names stable
- **Mapping**: keep row-to-client mapping in the route or a dedicated mapper,
  e.g. `worker/mappers.ts`

```typescript
function mapRowToClient(r: ProfileRow) {
  return { created_at: r.createdAt, owner_id: r.ownerId, profile_url: r.profileUrl };
}
```

## Environment Variables

| Name                        | Where                            | Notes                                     |
| --------------------------- | -------------------------------- | ----------------------------------------- |
| `CREDENTIAL_ENCRYPTION_KEY` | `.dev.vars`, `wrangler secret`   | Base64 32-byte AES-GCM key; required      |
| `VITE_GEMINI_API_KEY`       | `.env.local` / build environment | Optional, browser-exposed, Gemini only    |

Provider tokens are **not** environment variables. They are saved per User via
`PUT /api/account/credentials`, encrypted, and read only for that User's
scrapes. Never add `APIFY_TOKEN`, `TREG_TOKEN`, or a database URL to
`.env.example`, `.dev.vars.example`, `wrangler.jsonc`, or code.

## Input Validation

Validate every request body field in the route. Zod schemas live in
`lib/validation.ts`; Worker routes may also validate directly when the shape is
small:

```typescript
const body = await parseJsonBody(ctx.request);
const email = typeof body.email === 'string' ? body.email.trim() : '';
if (!isEmail(email)) return error(400, 'Invalid email address');
```

- Keep password minimum length and URL pattern checks consistent with existing
  routes.
- Validate `page`/`pageSize` before using them in `limit`/`offset`.
- Return `error(status, message)` for client errors; do not leak provider or
  database internals.

## Error Handling

```typescript
try {
  const items = await provider.scrapeProfiles({ urls, tier }, credential.token);
  return json(items);
} catch (err) {
  return providerFailure(err, 'Scraping failed. Try again later.');
}
```

- Provider failures map to a 502 with a user-safe message.
- Use the existing `providerFailure` helper in `worker/routes/scrape.ts` rather
  than inventing a second error shape.
- Frontend API errors are read with `readApiError()` from `services/http.ts`.
- `ErrorBoundary` catches render errors only, not event handlers or async work.

## Testing

Tests run inside workerd through `@cloudflare/vitest-plugin`; `env.DB` is a
real local D1 database with `drizzle-d1/` applied by `test/apply-migrations.ts`.

```bash
pnpm test --run
pnpm test --run test/leads.test.ts
```

- Drive routes through `worker.fetch(new Request(...), env)` where practical.
- Do not add a DOM test environment: there is no jsdom or Testing Library in
  this repo. Component behavior is covered by route/schema tests and the preview
  smoke checklist.
- Use `test/fixtures/` for provider payloads instead of live calls.

## Security Guidelines

- Never commit `.dev.vars`, `.env.local`, or real credentials.
- Encrypt Scrape Credentials with the existing AES-GCM helper; never return
  plaintext tokens to the client, log them, or put them in error messages.
- Keep session tokens opaque; never build a client-trusted auth claim.
- Check `requireUser` / `requireAdmin` on every non-public route.
- Use Drizzle bound parameters; never interpolate user input into SQL.
- Scope every saved record and Scrape Job by owner.
- Do not add Node compatibility flags or Node-only dependencies to satisfy an
  import; rewrite the code with Web APIs.

## Common Gotchas

- **Local state**: `pnpm dev` uses the top-level Wrangler config and a local D1
  under `.wrangler/state`. Re-run `pnpm db:migrate:local` after schema changes.
- **Env selection**: `CLOUDFLARE_ENV=preview|production pnpm build` must precede
  a deploy, otherwise the generated config carries the top-level D1 binding.
- **D1 commands with env**: pass `--config wrangler.jsonc` (the Vite plugin also
  writes a generated config) and `--env <name>` for remote environment
  databases.
- **Placeholder ids**: `wrangler.jsonc` ships placeholder database ids so
  `deploy --dry-run` works offline; replace them before a real deploy.
- **Env files in output**: the Vite plugin writes a `.dev.vars` containing local
  env values into `dist/<worker>/`; the deploy scripts remove
  `dist/*/.dev.vars` first, and `dist/client/.assetsignore` excludes it from the
  asset upload. Verify the upload does not include it.
- **D1 parameter cap**: at most 100 bound parameters per statement; use
  `chunk(items, 90)` for `inArray` and multi-row inserts.
- **Workers Free limits**: 10 ms CPU, 50 subrequests, 50 D1 queries per
  invocation. Company scrapes are chunked for this reason; do not add long
  loops or per-item requests.
- **TypeScript `any`**: minimize it; external provider JSON is the main
  exception, and it should be normalized at the provider boundary.
- **React lazy imports**: must be wrapped in `<Suspense>`.
